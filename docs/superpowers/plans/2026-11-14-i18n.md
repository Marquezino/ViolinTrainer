# Internationalization (English and Brazilian Portuguese) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every user-facing text available in English and Brazilian Portuguese, chosen from the browser and switchable by hand, with note names in letter names (English) or solfège (Portuguese).

**Architecture:** Lower layers (ABC checker, engine, tolerance validation) stop producing English sentences and return codes plus data (MIDI numbers, character positions). A new `src/i18n/` module holds one typed message module per language, locale detection and persistence, and a React context; the UI turns data into text through it. The compiler enforces that every language has every message.

**Tech Stack:** TypeScript, React 19, Vite, Vitest (node environment, no DOM testing library), Playwright. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-14-i18n-design.md` (beads issue ViolinTrainer-3l2)

## Global Constraints

- No new runtime or dev dependencies; no i18n library.
- Locales: `en` and `pt-BR`. Menu labels: "English", "Português (Brasil)".
- Note names: `en` = C D E F G A B; `pt-BR` = Dó Ré Mi Fá Sol Lá Si. Accidentals ♯ ♭ in both. Octaves use scientific numbering in every language (middle C = C4 = Dó4).
- A missing or extra message in any language must fail `npm run typecheck`. No runtime fallback to English or to raw keys. The only untranslated text shown is abcjs's own warning detail, always inside a translated sentence.
- Detection, judging and scoring behaviour must not change.
- Saved locale lives in `localStorage` under the key `violin-trainer.locale`; every access in try/catch.
- The app name is the message `appName`, "Violin Trainer" in both languages; `document.title` is set from it.
- Portuguese wording: natural Brazilian Portuguese for a beginner, possibly a child: short sentences, "você", encouraging; same meaning as the English. Fixed strings used by tests are listed in Task 5.
- Public repo: no personal details of users anywhere.
- Before each commit: `npm test` and `npm run typecheck` pass.

## Review Focus

1. **Browser languages without an exact match** (`pt`, `pt-PT`, `en-GB`, `fr-FR`, empty list): `pt*` → `pt-BR`, `en*` → `en`, the first matching entry wins, anything else → `en`. Pinned in Task 3.
2. **Unusable saved value or storage** (`localStorage` throws on read or write; saved value `'xx'` or `'pt-PT'`): the app still starts, uses detection, and does not crash when switching. Pinned in Task 3.
3. **Solfège at accidentals and octave boundaries**: B♭3 → `Si♭3`, F♯4 → `Fá♯4`, B3 → `Si3`, C4 → `Dó4` (octave comes from the MIDI number, not the name). Pinned in Task 1.
4. **abcjs warnings in unexpected shapes**: a warning without the `Music Line:L:C:` prefix still yields an `abcSyntax` problem with its whole text as detail and no position; HTML is stripped. Pinned in Task 2.
5. **Switching language with custom ABC typed in the box**: the typed ABC is kept and its problems re-render in the new language; custom ABC without `T:` shows the translated "untitled" text. Pinned in Task 5 (e2e).

**Interfaces:**

- Produces, in `I18nProvider.tsx`: `I18nProvider({ children })` and `useI18n(): { locale: Locale; t: Messages; setLocale(locale: Locale): void; format(preferFlats: boolean): Formatters }`. Initial locale: `detectLocale(loadSavedLocale(), navigator.languages ?? [])`. `setLocale` saves with `saveLocale`. An effect sets `document.documentElement.lang = locale` and `document.title = t.appName`.

Wiring decisions:
- `main.tsx` wraps `<App />` in `<I18nProvider>`.
- `ExercisePicker` keeps each sample's `id` next to its parsed exercise and calls `onPick(exercise, sampleId: SampleId | null)`. `App` keeps both in state and passes them to `PracticeScreen`. The shown title is `t.sampleTitles[sampleId]` for samples, else `exercise.title ?? t.untitled`.
- Starter ABC in the text box uses `T:` + the starter title from the current language, set only as the initial state: switching language never replaces typed text.
- Problems in the picker render through `t.abcProblems[p.code](p, format(result.preferFlats))` (failure) or the parsed exercise's `preferFlats` (warnings). List keys use the index.
- Language menu: a `<select aria-label={t.languageLabel}>` in a header row at the top of the picker, one `<option value={locale}>` per `LOCALES` entry labelled with `LOCALE_LABELS`. Not on the practice screen.
- Feedback and needle format `playedMidi` with `format(exercise.preferFlats).note`. Points, dB and cents go through `format(...).number`.
- `ScoreView` labels use `fingeringLabel(target.fingering, t.noteNames)`; include `t.noteNames` in the effect's dependencies.
- In `index.css`, hide the abcjs-drawn title on the practice score only: `.practice .score .abcjs-title { display: none }` (the picker's live preview keeps it).
- `playwright.config.ts`: add `locale: 'en-US'` to `use`.
